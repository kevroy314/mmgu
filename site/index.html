Rooms of the hall

What's inside

The Archive

Item catalog

Drop a screenshot of an inspect window; it's read, checked by a person, and saved with where it drops.

The Vault

Guild bank

Monsters & Memories has no guild bank, so the hall tracks bank characters, deposits and withdrawal requests.

The Notice Board

Requests & trade

WTS / WTB listings that expire, and requests for items or services with claim, done and thanks.

The Crafters' Hall

Tradeskills

Who has which tradeskill at what level, recipes, and "who can make this?"

The Muster Roll

Roster

Members, mains, alts and bank characters. Paste /who to update levels.

The War Table

Events & loot

Sign-ups by role, reminders, attendance, transparent loot history and a calendar feed.

The Watch

Spawn timers

Report a time of death; the hall counts down the window and pings whoever's watching.

The Beacon

Stream overlay

OBS overlays that show item cards, discoveries, spawn windows and events live.

Everything anyone changes is in the audit log. Anything a machine suggests (an AI screenshot read, an import, Claude) waits for a person to approve it.

About fifteen minutes

Get started

  1. Get a machine and Docker

    Any always-on PC, a small VPS or a Google Cloud VM works. Install Docker. For reading screenshots locally you'll also want an NVIDIA GPU with 8 GB or more; without one, the hall can use Claude for a fraction of a cent per screenshot, or you can type items in by hand.

  2. Download and configure

    git clone https://github.com/kevroy314/mmgu.git
cd mmgu
cp .env.example .env    # set MMGU_GUILD_NAME, MMGU_BASE_URL and MMGU_SECRET_KEY

    Make yourself leader: put MMGU_BOOTSTRAP_LEADERS=discord:<your Discord user id> in .env.

  3. Start the hall

    docker compose up -d                                  # http://localhost:8420
docker compose --profile ai up -d                     # optional: local AI on an NVIDIA GPU
docker compose --profile ai-setup run --rm ollama-pull # once: download the vision model

    Just exploring? Set MMGU_AUTH_MODES=dev and MMGU_DEV_LOGIN=true, run docker compose exec hallkeeper mmgu seed-demo, and log in with any name. Never leave dev login on for a hall others can reach.

  4. Connect Discord

    Create the bot and paste its settings into .env (below). The web hall shows a Set up Discord bot badge to leaders until it's connected, with the exact values to copy.

  5. Open the Steward's Office

    In the web hall, pick Discord channels for each room, adjust who can do what, and turn on any add-ons your guild wants.

Slash commands, buttons, channel posts

Discord setup

  1. At the Discord Developer Portal, create an application. On the Bot tab, reset and copy the token and turn on Server Members Intent.

  2. On the OAuth2 tab, copy the Client ID (and Client Secret for "Log in with Discord"), and add the redirect <your hall URL>/auth/discord/callback.

  3. MMGU_AUTH_MODES=discord
MMGU_DISCORD_TOKEN=...
MMGU_DISCORD_CLIENT_ID=...
MMGU_DISCORD_CLIENT_SECRET=...
MMGU_DISCORD_GUILD_ID=...          # right-click your server → Copy Server ID
MMGU_DISCORD_ROLE_MAP=<role id>=officer,<role id>=member,<role id>=banker

    Restart with docker compose up -d, then invite the bot with the bot and applications.commands scopes. The badge in the web hall gives you the invite link.

Add-ons and the game's rules

Screenshot Reader check ToS

Reads item and bank screenshots with a local vision model (Ollama, Qwen3-VL) or Claude.

Ledger Sync ToS risk

A companion each player runs on their own PC that sends loot and kills from the game's local log files. Read-only.

Claude Integration no game data

An MCP server so Claude Code or Claude Desktop can search the hall and suggest changes for a person to approve.

Where the line is

The core hall never touches the game client. Add-ons that read game output carry a plain notice a leader must accept before they turn on, and the companion asks each player too. Hallkeeper never reads game memory or network traffic. Whether to use an add-on is each guild's and player's call. More on this.

Early Access moves fast

Built to change

New classes, stats, zones and tradeskills are edits to one game-pack file. A whole new system is mmgu new-module <id>: each module owns its tables, pages, Discord commands and migrations, and plugs into the others through events and extension slots. See docs/adapting.md and docs/architecture.md.
